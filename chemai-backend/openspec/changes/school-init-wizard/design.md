# Design: school-init-wizard

## Context

`/admin/school` 页（P0）已有学校信息表单。导入端点（`app/api/data_import.py`）请求模型均为 JSON rows（`RosterImportRequest`/`TeachingImportRequest`/`ExamImportRequest`），幂等语义在服务层（名册按学号去重、成绩同班同名同日期幂等、任教建档+关系）。前端无 XLSX 依赖。

## Goals / Non-Goals

**Goals:**
- 管理员自助完成学期初导数与新校初始化
- 复用端点幂等语义，界面不重复实现去重

**Non-Goals:**
- 服务端文件解析、XLSX 支持（CSV/粘贴足够；复杂表格让用户先转 CSV）
- 模板下载/列说明文档页（步骤内给列名提示即可）
- 修改导入端点与审计语义

## Decisions

**D1 — 纯前端 change，向导挂 `/admin/school`。** 学校信息步骤即 P0 表单的向导化包装（未初始化态 = 建校表单），不另起页面路由；导入三步为向导组件内步骤。

**D2 — 解析用轻量自研 CSV 解析（处理引号/换行转义），不引依赖。** 行 < 数千量级，性能无忧；列校验按端点请求模型字段做必填/类型检查，错误行标示但**允许剔除坏行后提交其余**（用户勾选），还是**整批阻断**？——选整批阻断（默认）+ 提供剔除坏行开关：数据导入场景错一行污染一批，宁可让用户修好。粘贴近列说明（学号/姓名/班级…）按请求模型字段名中文映射。

**D3 — 结果摘要直接渲染端点返回的计数结构。** 三端点均返回新增/跳过明细（data_import 服务层既有），不二次加工；失败行摘要原样展示。

## Risks / Trade-offs

- [CSV 编码/分隔符花样（Excel 导出 GBK、分号分隔）] → 解析层做 BOM/常见分隔符探测；预览阶段即可见乱列，用户可切换分隔符重解析。
- [大批量提交超时] → 名册按行分批（每批 N 行）提交并汇总摘要；成绩导入含逐题明细，分批阈值实施时按端点实测定。
- [向导被当成唯一导入方式，绕过脚本] → 不移除脚本；向导页注明「大批量历史迁移仍可用 API/脚本」。

## Migration Plan

纯前端；回滚 revert。
