# 星图"星空空间感"开源调研与优化方案

日期：2026-11-04 · 范围：教师端班级知识星图（`frontend/src/components/teacher/StarMap.tsx`）的视觉氛围升级；学生端星图作为后续阶段。

---

## 0. 结论摘要

**底座选型没有问题，问题全在"氛围层"。** 我们已经在用 react-force-graph-3d + three.js + UnrealBloomPass——这正是 Obsidian 3D Graph 插件、Cosmograph 之外整个知识图谱 3D 可视化生态的同一套底座。用户感觉"没有星空空间感"，根因是：**背景太空（单层 420 颗同质星尘 + 纯 CSS 渐变）、星没有形态差异（全圆形 sprite，无星芒）、画面是静态的（无闪烁）、连线太素（全景下像散点而非星座）、星系团没有整体形态（无星云核）**。五个缺口全部可以用"贴图/着色器/访问器"级别的小改动补齐，不需要更换任何依赖。

---

## 1. 现状诊断（为什么"没有空间感"）

代码证据（`frontend/src/components/teacher/StarMap.tsx`）：

| # | 现状 | 位置 | 缺什么 |
|---|------|------|--------|
| 1 | 背景 = CSS 径向渐变 `radial-gradient(#08101f→#020409→#000103)` | `StarMap.tsx:460-462` | 没有银河带、没有星云、没有纹理层次 |
| 2 | 背景星尘 = **单层球壳** 420 颗，同 size(7)、同色(0x8fa8c8)、同 opacity(0.35)，`PointsMaterial` 静态 | `StarMap.tsx:151-179` | 无视差层次（相机转动时背景"不动"）、无闪烁、无色温差异 |
| 3 | 数据星 = 圆形径向渐变 sprite，NormalBlending（防爆白的正确决定） | `StarMap.tsx:39-57, 351-360` | 无四芒/星芒形态；亮星暗星只差透明度，没有"恒星感" |
| 4 | 全画面零动画：星不闪、尘不动、只有相机 autoRotate 0.8 | `StarMap.tsx:246` | "活的星空"需要微动效（闪烁是最便宜的一种） |
| 5 | 连线 = 直线，默认 opacity 0.3，仅高亮链有粒子 | `StarMap.tsx:329, 331-338` | 全景下边几乎不可见 → "漂浮的点"而非"星座" |
| 6 | 6 册锚点聚簇是球形散布，无任何团级视觉容器 | `lib/starMap.ts:41-48` | 看不出"这是一个个星系团" |
| 7 | 相机无开场运镜（首帧直接 zoomToFit） | `StarMap.tsx:518` | 缺"进入宇宙"的第一印象 |
| 8 | bloom 链路已调稳（threshold 0.05 / strength 1.5 / radius 0.6，ACES 曝光 1.2），历次"爆白"教训都已注释在案 | `StarMap.tsx:180-207, 429-434` | **新增发光体必须继承这些教训**（见 §5 风险） |

另有一个顺带发现的性能点：`nodeThreeObject` 的 useMemo 依赖了 `[tex, highlight, ghostIds, selectedKp]`（`StarMap.tsx:404`），而注释自己说"sprite 绝不能随高亮/筛选重建"——实际上 sprite/标签创建时并不读这三个状态（逐帧透明度全走 `visRef`），依赖可以收缩到 `[tex]`。选中一次 = 全图对象重建一次 + 闪帧，这正是 hover 聚焦（P1-7）必须先修的闸门。

学生端（`pages/mobile/student/KnowledgeMapPage.tsx`）目前是**气泡分组列表图**，与星图完全无关——"记忆星图"的完整愿景最终要落到学生端（FSRS 可提取性 = 闪烁频率，见 `lib/starMap.ts:6` 注释预留），本方案 P2 给出路径。

## 2. 调研发现（一手来源）

### 2.1 对标项目

**vasturiano/3d-force-graph**（我们正在用的库，[GitHub](https://github.com/vasturiano/3d-force-graph) / [官方示例页](https://vasturiano.github.io/3d-force-graph/)）
- 官方 31 个示例中**没有 galaxy/starfield 示例**——"星系感"不是库给的，是场景装饰给的。相关官方姿势：`bloom-effect`（UnrealBloomPass 标准接法，与我们现实现一致）、`click-to-focus`（flyTo 已复刻）、`camera-auto-orbit`（巡航已用）、`curved-links`、`gradient-links`、`emit-particles`。
- [react-force-graph README](https://github.com/vasturiano/react-force-graph)（API 已核对，本仓库装的是 react-force-graph-3d 1.29.2）：`linkCurvature`（曲率半径，1≈半圆）、`linkCurveRotation`、`linkDirectionalParticles` 全家桶（speed/width/color/offset/`emitParticle(link)`）、`cameraPosition(pos, lookAt, ms)`、`controls`、`controlType`（trackball/orbit/fly）、`postProcessingComposer`。**方案 P1 需要的 API 全部现成，零新增依赖。**
- Obsidian 社区 3D 图谱插件（[apoo711/obsidian-3d-graph](https://github.com/apoo711/obsidian-3d-graph)，Rust+WASM 物理引擎版；[New 3D Graph](https://www.obsidianstats.com/plugins/new-3d-graph)）**全部建在 3d-force-graph 上**——底座相同，差距只在装饰层与物理手感。

**Cosmograph**（[官网](https://cosmograph.app/)）：自称最快 web 力导向渲染，GPU/WebGL 点云方案，showcase 有 68.8 万点（多伦多树图）。对我们规模（全校知识点 ~10² 量级）**性能不是瓶颈、点云风格也不是我们要的"照片级星空"**——它的启示是"点精灵 + GPU"的成本模型：几千颗装饰星在一次 draw call 内免费。

**Obsidian Graph View**（2D 力导向，[官方帮助](https://help.obsidian.md/plugins/graph)）：它的"空间感"来自交互而非 3D——hover 时邻域保持、其余淡出；距离/缩放平滑；颜色分组。这是上一轮差距分析（`openspec/changes/star-map-interactions/proposal.md`）的对标物，其交互我们已基本补齐；**这次缺的是它也没有的 3D 氛围层**。

**Spacekit.js**（[typpo/spacekit](https://github.com/typpo/spacekit)，开源天文可视化库，驱动 Asterank）：真实星空的两种做法并存——① 天空球贴图（大球 BackSide 内贴 ESA 银河/NASA Tycho 全景）；② 真实星表点云（`Stars` 类，自带评价："**more performant but less visually stunning**"）。这句话直接支撑本方案的 P0-2：**要"哇"，用天空球；要性能，用点云；我们两者都上（点云星尘 + 程序化星云天空球），各司其职。**

**"记忆星图"同名开源项目**：中文检索未发现同名项目（Anki/Obsidian 生态里的记忆类插件均为卡片侧工具，如 [PKMer Anki 插件合集](https://pkmer.cn/tags/anki)、[Sprout](https://www.reddit.com/r/ObsidianMD/comments/1qztt9u/)）。"记忆星图"在开源世界没有现成答案，我们的"掌握度=亮度、作答量=大小、薄弱=暗星+星芒"编码本身就是差异化设计——**要抄的不是某个项目，是天文可视化的氛围手法**。

### 2.2 可直接引用的技术素材

| 手法 | 一手来源 | 用法 |
|------|----------|------|
| UnrealBloom 辉光链路 | three.js 官方示例 `webgl_postprocessing_unreal_bloom`（已接入，`StarMap.tsx:180-207`） | 保持现状，新发光体亮度压阈值下 |
| 着色器驱动 Points（每点属性 + `gl_PointSize` 距离衰减 + fragment discard 圆形） | three.js 官方示例 [`webgl_points_waves`](https://raw.githubusercontent.com/mrdoob/three.js/dev/examples/webgl_points_waves.html)：`gl_PointSize = scale * (300.0 / -mvPosition.z)`，per-point `scale` attribute | **闪烁星尘**：在此模式上加 per-point `phase` attribute + `uTime` uniform，顶点着色器 `sin(uTime + phase)` 调 alpha/size |
| 天空球背景 | Spacekit 的 skysphere（ESA 银河 / NASA Tycho 预设） | 大球 BackSide + 星云 shader 或全景贴图 |
| 银河全景照片 | [ESO eso0932a](https://www.eso.org/public/images/eso0932a/)：6000×3000，免费使用但**必须显著标注 credit "ESO/S. Brunier"** | 照片级方案 B 的素材（署名义务见 §5） |
| 曲线连边 | `linkCurvature` / `linkCurveRotation`（README 已核对） | P1-5 星座连线 |
| 深度感衰减 | 我们已有（`StarMap.tsx:368-376` 的距离-尺寸/透明度） | 保持，这是空间感的地基 |

## 3. 两条路线的取舍（先说为什么不换轮子）

**路线 A：留在 react-force-graph-3d，只做氛围层**（推荐）
- 优点：交互层（搜索/高亮/筛选/标签/布局持久化）已交付且测试覆盖；官方 API 全覆盖 P0/P1 需求；风险全部局限在"装饰物"，出问题可单独摘除。
- 成本：见 §4，全部是 three.js 场景内加对象/换贴图/换材质，无数据层改动。

**路线 B：换 Cosmograph / 自写 GPU 点云**
- 换来的是规模（几十万点）和点云风格，**牺牲**：force-graph 的力引擎访问器（`d3Force` 聚簇已深度使用）、CSS2D 标签链路、粒子/曲率 API、已调稳的 bloom 链路，交互层全部重写。为"氛围"换底座是负收益。**否决。**

## 4. 优化方案（P0 → P2，可分批迭代）

### P0 — 空间氛围（一批改动，观感跃迁；预计 1 个 openspec change）

| # | 改动 | 实现要点 | 视觉收益 |
|---|------|----------|----------|
| P0-1 | **三层视差星尘**（替换现有单层 420 颗） | 3 层 `THREE.Points`：远层 r≈3000-4400（~1500 颗，size 4-6，opacity 0.22，偏冷白）、中层 r≈1600-2600（~600 颗，size 7-10，opacity 0.32，冷暖混合：白/淡金/淡蓝）、近层 r≈500-1100（~80 颗，size 12-16，opacity 0.4，加 2-3 颗册色点缀）。`depthWrite:false`、`renderOrder:-1` 不变。相机一转，层间相对运动 = 天然纵深 | 星空从"贴纸"变"深井" |
| P0-2 | **星云天空球** | 半径 ~5200 大球 `BackSide` + 自写 `ShaderMaterial`：hash 噪声静态微星（数千颗，GPU 生成零内存）+ 2-3 层 fbm 星云雾（取册色的极暗变体：teal/紫/品红，亮度 ≤0.05 防 bloom 爆）+ 极缓时基流动。`renderOrder` 最先、`depthWrite:false`、`fog:false` | 背景从纯黑渐变变成"有物质感的深空" |
| P0-3 | **闪烁（twinkle）** | **只给装饰层**（P0-1 各层 + P0-2 微星），顶点着色器 `alpha *= 0.75 + 0.25*sin(uTime*speed+phase)`；**数据星本体绝不闪**（bloom×透明度联动是历次爆白雷区，且亮度编码掌握度、不能被动画污染） | 画面"活着"，数据编码不被污染 |
| P0-4 | **暗星四芒星芒** | `glowTexture()` 增加四芒变体（canvas 上叠两条正交高斯光带，十字 45° 微旋），仅 `kind==='dim'` 的星用星芒贴图 + core 略大 | 薄弱星 = 肉眼可辨的"变星"，数据编码获得形态维度 |
| P0-5 | **`nodeThreeObject` 依赖收缩**（顺手修） | useMemo 依赖 `[tex]`，高亮/幽灵/选中全走 `visRef`（机制已在，`StarMap.tsx:298-300`） | 消除选中闪帧 + 为 hover 聚焦解锁前提 |

### P1 — 星座叙事（第二批）

| # | 改动 | 实现要点 |
|---|------|----------|
| P1-5 | **曲率星座连线** | `linkCurvature={0.3}` + 曲率随边长衰减；默认透明度按长度分级（短边 0.35 / 长边 0.12），全景下先修链呈"星座图"而非直线网格 |
| P1-6 | **星系团星云核（halo）** | 每册锚点处一个大尺度极淡辉光 sprite（册色，scale ≈ 团半径×2，opacity 0.03-0.05，NormalBlending，`depthWrite:false`），六个"星云核"让星系团结构一眼可读；亮度严格压 bloom 阈值下 |
| P1-7 | **hover 邻域聚焦**（Obsidian 招牌） | hover 星 = 一度邻域保持 + 其余淡至 0.15；完全复用 `visRef` 逐帧透明度机制，只加一个 hover 状态位（依赖 P0-5 先落地） |
| P1-8 | **开场运镜** | 首次 `onEngineStop` 前：相机从 d≈2200 偏轴位 2s 缓动到 zoomToFit 位（`cameraPosition(pos, look, 2000)` 现成 API）；`prefers-reduced-motion` 时跳过（合规沿用 R-M1） |

### P2 — 生命感与学生端（后续独立 change）

- **P2-9 怠速漂移与偶发流星**：无输入 10s 后相机缓慢 drift；每 20-40s 一颗背景流星（装饰层线段动画，不进交互）。
- **P2-10 学生端记忆星图**：抽 `StarMap` 为共享组件（`components/star/`），学生数据注入：亮度=个人掌握度、**闪烁频率=FSRS 可提取性**（`lib/starMap.ts:6` 注释早已预留）、灰星=未作答。学生"看自己的星空"——这是产品命名"记忆星图"的完整兑现，也是与所有开源图谱工具真正的差异点。
- **P2-11 移动端降级**：UA/`devicePixelRatio` 检测，星尘减半、关 bloom、天空球降分辨率。

## 5. 风险与合规（全部来自本项目已有的血泪注释）

1. **bloom 爆白三前科**（`StarMap.tsx:180-207, 429-434` 注释记录）：bloom 重复叠加、白环过亮、Additive 重叠累积。新发光体（天空球、halo、星芒、流星）一律：亮度 ≤0.05-0.1、NormalBlending、`depthWrite:false`、幂等守卫（`scene.userData.*` 模式）。
2. **sprite 重建闪帧**：所有新视觉走"贴图变体 + 访问器"，禁止在 nodeThreeObject 里按交互状态分支。
3. **reduced-motion**（R-M1）：闪烁/流星/漂移/开场运镜都必须在 `prefers-reduced-motion: reduce` 时停用或静止。
4. **ESO 素材署名**：若选照片级天空球（P0-2 方案 B），页面必须显著标注 "ESO/S. Brunier"；**推荐方案 A（程序化 shader 星云）为零版权负担且色相可控**，故为默认。
5. **数据编码不可污染**：亮度=掌握度、色相=册、大小=作答量（`lib/starMap.ts:1-6`），装饰层只许用"册色的暗变体"和白色系，禁止引入新语义色。

## 6. 建议落地顺序与验证

1. **P0 一个 openspec change**（建议名 `star-map-atmosphere`）：P0-1..5 一次交付，验证台截图对比 + `prefers-reduced-motion` 断言 + bloom 幂等回归（多次 bindFg 不叠 pass）。
2. P1 视用户反馈拆第二批（hover 聚焦建议必做——它是 Obsidian 式"空间感"的交互支柱）。
3. P2 学生端单独立 capability（`star-map-student`），依赖教师端氛围层稳定。
