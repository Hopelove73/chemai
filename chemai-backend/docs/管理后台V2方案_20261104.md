# 管理后台 V2 方案（决策锁定版）

> 2026-11-04。取代 `管理后台建设方案_20261104.md` 中关于"管理端"的信息架构部分（P0/P1/P2 的**能力**仍然有效，**组织方式**作废）。
> 调研依据：Moodle / Canvas / Open edX / Google Classroom / 中国校务；Dify / FastGPT / RAGFlow / Coze / Langfuse / LangSmith；教育 SaaS 看板与导航形态。结论详见会话记录。

## 0. 决策记录

| 议题 | 决定 | 依据 |
|---|---|---|
| 导航形态 | **双模式侧栏**：侧栏底部「管理中心」→ 整栏切换为管理导航（4 组折叠），顶部「← 返回教学」 | 管理员兼教师，需模式边界且一键往返；11→15 项已超单栏上限 |
| RAG 深度 | **三页 P0**：问答日志 + 召回测试 + 评测回归 | 调研共识：逐请求证据链是"运营后台 vs 知识库页"的分水岭 |
| 账号中心 | **学生 / 教师 / 家长 三页独立** | 教师端 StudentsPage 是教学视角，管理端要账号生命周期视角 |
| 角色权限 | **只读展示**（矩阵 + 授权关系 + 数据范围解释） | 权限真源留在代码，300+ 测试围绕它写；可编辑等于重构 RBAC |

## 1. 基线（真实数据）

```
student_answers  76,202 条   2025-09-04 ~ 2026-10-20   近7天 0 / 近30天 15
warning_logs     211 条全部 pending，processed = 0     → 「处理率」恒为 0
parents          680 条绑定记录，accounts 中 parent 仅 2 个   → 家长激活率 0.3%
accounts         admin 1 / teacher 5 / subject_lead 1 / student 340 / parent 2
exam_records     7,595 条
accounts.last_active_date 存在 → 可做活跃统计
知识检索调用点    agent/tools/tutoring.py:312（全文唯一）→ 埋点位置干净
```

**三条结论**：
1. 任何"近 N 天"图表在演示库上都会空 —— 趋势图改为**近 12 个月**并标注数据截止日。
2. 「预警处理率」无闭环数据（`processed=0`），改为"识别 / 已处理"两段 + 明示"闭环未接入"，不画假漏斗。
3. 家长**不是**"管理已有账号"，而是"680 人里 678 人没激活"——这是管理端最有信息量的一张图。

## 3. 逐页规格

### 3.1 学生账号 `/admin/students`（新）

**与教师端 `/students` 的分工**：那边是"看学情"（正确率、障碍类型、诊断），这边是"管账号"。

- 列表列：学号 / 姓名 / 班级 / **账号状态**（有账号·无账号）/ 登录状态（`last_active_date`）/ 家长绑定数 / 状态（pending/approved）
- 筛选：班级、账号状态、绑定状态、审批状态、关键词
- 批量动作：批量开通账号（生成默认密码）、重置密码、转班、停用/启用、删除
- 单行：详情抽屉（基本信息 / 账号 / 绑定家长 / 操作时间线）
- **空态规则**：无账号学生单独一个筛选视图，附「批量开通」按钮（命中当前 340 学生里可能存在的无账号者）

### 3.2 教师账号 `/admin/teachers`

现有 `AdminUsersPage` 的「教师审批 + 教师账号」两个 Tab 拆出来，行为不变。

### 3.3 家长与绑定 `/admin/parents`（新）

两个视图（Tab）：

**Tab A · 家长账号**：手机号 / 姓名 / 账号状态 / 绑定子女数 / 最近活跃
- 动作：批量开通、重置绑定码、停用
- **激活漏斗卡**（本页核心）：`绑定记录 680 → 有账号 2 → 近 7 天活跃 0`，每一段可点击下钻到名单

**Tab B · 绑定关系**：家长 ↔ 学生、关系、绑定码、状态（active/revoked）、创建时间
- 动作：单条解绑、批量解绑、按学生查家长、按家长查子女
- 异常视图：重复手机号、未激活超 7 天、一孩绑定超过 3 位家长

### 3.4 班级与年级 `/admin/classes`（新）

- 组织树：年级 → 班级（含学生数、班主任、任课教师数）
- 班级 CRUD（现有能力）+ 年级 CRUD（后端 `grade.py` 已有）
- 转班入口复用学生账号页的批量转班

### 3.5 KB 生产 `/admin/kb`（改造现有）

保留：状态卡、审校队列、触发摄取、词典/标签同步。
**新增**：文档列表（按册 → 文档 → chunk 三级），chunk 级 编辑 / 禁用 / 重建，质量标记（公式/表格/疑似乱码）。
> chunk 治理与本 change 的优先级：**P1**，先不动（避免与审校流程打架）。

### 3.6 召回测试 `/admin/rag/retrieval`（新）

- Query 输入 + 过滤（册 / 知识点 / 文档）
- 配置面板：检索方式、TopK、阈值、图增强开关 → **只影响本次测试**，不写默认配置
- 结果列表：排名 / chunk 内容 / 分数 / 来源文档 / 是否图扩展召回
- 动作：保存为金标问题、标记 bad case、跳转编辑 chunk
- 对比模式（P1）：A 配置 vs B 配置并排

### 3.7 问答日志 `/admin/rag/traces`（新，★核心）

**列表**：时间 / 学生或会话 / 问题 / 命中数 / Top1 分数 / 是否拒答 / 反馈 / 延迟
筛选：时间、拒答、零召回、低分命中（Top1<阈值）、负反馈、学生、班级

**详情（完整证据链）**：
```
① 问题 + 会话上下文
② 检索配置快照（方式/TopK/阈值/图增强）
③ 命中 chunk 列表（内容 / 分数 / 排名 / 来源文档 / 是否图扩展）
④ 送入模型的上下文（摘要 + token）
⑤ 模型回答 + 引用
⑥ 模型 / 延迟 / KB 索引版本
⑦ 学生反馈 + 运营标注
```

**动作**：标好/坏（含原因：检索错 / chunk 差 / 缺知识 / 幻觉 / 不完整 / 超纲 / 误拒）→ 修正答案 → **回流金标集** → 一键禁用命中的坏 chunk

### 3.8 评测与回归 `/admin/rag/evals`（新）

- 金标集：问题 / 期望 chunk / 期望答案 / 章节课标签 / 状态（active / draft / stale / paused）
- 跑评测：选配置 → 出指标（期望命中率 / 拒答正确率 / 忠实度 / 相关性）
- **baseline vs candidate 逐题 diff**：新增失败 / 修复项，可下钻
- 发布门禁：不达标不允许发布 KB 变更（P1 硬门禁，P0 只提示）

### 3.9 操作日志 `/admin/logs`（升级）

补字段：`actor_role` / `result`(success/failed/denied) / `before`→`after` / `request_id`。
筛选条补齐：目标类型、结果、角色、时间段；详情抽屉 + CSV 导出。

### 3.10 运行时开关 / 平台提权 / 学校设置

保持现状（这三个上一轮已交付且验证通过）。

### 3.11 角色与权限 `/admin/roles`（新，只读）

三个 Tab：
- **角色一览**：7 角色 + 中文名 + 一句话职责 + 人数
- **权限矩阵**：资源 × 动作，从 `ROLE_PERMISSIONS` 自动生成（**只读**），标注"权限真源在代码，修改需发版"
- **数据范围解释**：每个角色的 `RequestScope` 语义（全校 / 本年级 / 本学科 / 任教班 / 本人 / 绑定子女），配一句"为什么这个按钮看不到"

## 5. RAG 闭环：数据模型与埋点

### 5.1 新表 `qa_traces`

```text
trace_id            PK
user_id, role       学生/教师
conversation_id
question            原始问题
rewritten_query     查询改写（若有）
retrieval_config    JSON  检索方式/TopK/阈值/图增强开关
hits                JSON  [{chunk_id, document_id, score, rank, from_graph, doc_title, chapter}]
zero_hit            bool  命中数 = 0
top1_score          float
answer              TEXT
citations           JSON
refusal_flag        bool
refusal_reason      str
latency_ms          int
model_name          str
kb_index_version    str
feedback            up / down / none
feedback_text       str
ops_label           good / bad / null
bad_reason          str  检索错/chunk差/缺知识/幻觉/不完整/超纲/误拒
created_at          DATETIME
```
索引：`created_at`、`user_id`、`refusal_flag`、`zero_hit`、`top1_score`。

### 5.2 埋点位置

`agent/tools/tutoring.py:312` 是全文唯一的 `build_kb_context` 调用点，`kb_out` 已含 hits / miss 标记 / 渲染上下文 —— 在回答产出后**同事务外异步写一条 trace**（失败不影响回答）。

### 5.3 指标定义（落库、可看板）

```
检索命中率 = 有 hits 的请求 / 总请求
零召回率   = zero_hit 的请求 / 总请求
拒答率     = refusal_flag / 总请求
误拒率     = ops_label=bad & bad_reason=误拒 / 本可回答请求
负反馈率   = feedback=down / 总请求
低分命中率 = top1_score < 阈值 / 有 hits 的请求
```

## 8. 风险与非目标

**风险**
- [qa_traces 埋点拖慢回答] → 异步写 + 失败静默，绝不影响回答链路
- [八图概览查询慢] → 班级/知识点聚合走 `kb_error_rate` 既有缓存口径；必要时加物化表
- [拆页导致旧书签失效] → `/admin/users` redirect 到 `/admin/teachers`
- [家长"批量开通"需要发密码] → 复用教师审批的一次性凭据弹窗模式，明文只展示一次

**非目标**
- 权限矩阵可编辑（只读展示）
- chunk 级治理与解析配置（P1，另立 change）
- 多租户 / 跨校聚合 / A-B 灰度
- 把 `/integration` 搬进管理态
- 移动端管理界面
