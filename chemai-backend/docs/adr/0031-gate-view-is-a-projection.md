# ADR-0031: 门（确认卡）的视图是投影，不是第二份真源

**Date**: 2026-10-20
**Status**: Accepted（来源：`docs/门视图契约-评审输入-20261020.md` 的 eng review，
逐条裁定 D1–D7；实施拆在 T1–T7，见该文档的评审结论）

## Context

确认门（老师批准 / 打回 / 放弃）的**生命周期**有真源：`agent_gates` 那一行（ADR-0015、
ADR-0030 已经把它钉成权威）。但**会话时间线**上没有契约 —— 卡片此前只在 SSE 里由
`gate_open` 事件驱动渲染，而事件会丢：断流、重连、以及「门是上一轮开的」这三种情形下，
库里那扇门是开着的，老师屏幕上却没有卡。

那个形态的真实后果不是「少一张卡」：guard 把「库里还有 open 的门」当成「有一张卡在等
老师」，于是拒掉 agent 的**一切**工具调用。卡看不见 ⇒ 老师无法决定 ⇒ 门永远关不掉 ⇒
整条计划卡死。文档里记作 A5，是「死路」而不是「不好看」。

同一族还有第二笔账：`agent_gates` 是**当前态**表，批准之后再开门会覆盖门面，
`decided_at` 也等着被下一轮改写。于是「上一版是怎么被处置的、谁批的」在门行上留不住，
而当时唯一能回答它的 `agent_gate_decisions` 表**建了但全仓没有写入方** —— 验收里
「可回放」这一条没有数据来源。

## Decision

### ① 视图是投影，不是副本

卡片的唯一真源是门行；会话时间线里**不存**门的内容，也不存第二份状态。
会话里能存的只有指针（`gate_id`），内容一律回表查。

由此推出的两条**不做**：

- **不做消息化**（把「这里有张待批卡」写成会话历史里的一条产物）。那会引入第二份真源，
  而且门会进 checkpointer 的 `messages` —— 模型下一轮会读到自己写过的那张卡。
- **不给卡片存「位置」**。`AgentGate` 没有消息锚点列，而一个会话同时只有一扇 open 门，
  卡永远落在时间线尾部就是正确位置。真需要锚点时再加列，不预埋。

### ② 回合边界显式，且「怎么到达前端」可以退化

门开出 = 该轮**正常结束**（不是异常、不是被拦），后续不再有新的模型调用。

**关键的一句**：这条说的是「不许有下一次调用」，不是「同一批并行调用要被掐断」。
`tool_calls` 并行发放时，同一批里的其它调用已经发出去了（`GuardState._gate_lock`
存在的原因就是那次「双门齐开」实测）。契约措辞按「下一次模型调用为 0」成立，
不按「本轮工具调用总数为 0」。

到达前端这件事**允许退化**：`gate_open` 只是实时加速，**不是**真源。真源是「流结束后
重读一次历史投影」——事件丢了、门是上一轮开的，都由这一次重读兜住。
不新增 `turn_end` 事件类型：`run_paused` 的语义是**系统暂停**（超时/断线/报错），
「等待人工」与它是两件事，混用会让前端的暂停文案说错话。

### ③ 决策是三值 + 打回带反馈，不是一次性 edit

`approve / reject / abandon` 三个动作，`reject` 带反馈进版本链（审批归零、重新确认）。

**不做**「改参数 + 批准」的一次性 edit。原因不是工期，是安全边界：重放前有两道
fail-closed 校验（`verify_replay_payload`）——门行的 `args_hash` 与**即将执行的那一份**
必须一致。在决策那一刻改 kwargs，必然命中第二道，调用被拒；要让 edit 生效就得在
决策时重写 `args_hash`，那等于把「我批的和我要执行的是同一份」这条保证让位给
「批准时可以顺手改」。

「改一句再发」的诉求由 `reject + feedback → revise_draft` 满足，代价是多一次确认。

### ④ 决定的落点是账本，不是门行

`agent_gate_decisions` 是「谁、什么时候、对哪扇门做了什么」的唯一来源，只 insert。
写入**必须**在工作单元里（ADR-0021）：账本和它描述的那次动作同一次提交。
账记上了而动作没跑，比不记更糟 —— 下一次重试会拿着一条假凭据。

门行只负责当前态（`status`），终态卡展示用的文案/动作从门行补，归属与时间取账本。

## Consequences

- 前端 `ChatPage` 在一轮流**正常**结束时，若手里没有待批门卡，重读一次历史。
  条件不能去掉：无条件重拉会让每一轮都拉一份完整历史并重建整个列表，
  代价压在最常见的路径上，而缺卡本来就是异常态。
- 历史接口的 `gate`（待批）与 `closed_gates`（已处置）是同一套投影的两段，
  前端复用同一张卡片的待批态与终态渲染，不另造组件。
- 布尔门（`kind='boolean'`）同样适用：它没有草稿，所以没有可修订的版本链，
  `reject` 对它是「不执行，说一句为什么」，不是「改一版再来」。
- 放弃（abandon）与批准（approve）都要记账；只有关门的路径不记账，等于账本永远空。
- **已知保真度缺口**：终态卡的**文案**取门行现值，不是决定当时的文案。打回后重开门，
  上一张「已打回」卡会显示修订版的新文案。决定人、时间、决定类型都是准的，只有这句话不准。
  要修就得把文案快照进账本（`detail` 已被占用为反馈/版本载荷），那是加字段的事，单独一轮。

## 不做什么

- 不做消息化（第二份真源 + 模型上下文污染）。
- 不做一次性 edit（与 `args_hash` 的 fail-closed 相冲）。
- 不新增 `turn_end` / `gate_snapshot` 事件类型（`gate_open` + 流结束重读已经够）。
- 不给 `AgentGate` 加「位置」列。
- 不改确定性重放本身（ADR-0013 / ADR-0015 已经做对）。
