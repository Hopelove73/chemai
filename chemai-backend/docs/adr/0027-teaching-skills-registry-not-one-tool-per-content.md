# ADR-0027: 教学技能走注册表，不给每种内容各造一个工具

**Date**: 2026-03-30
**Status**: Accepted（用户裁定：「全部同意」，能力升级 grilling 第 1 轮 Q8）

## Context

对标 WorkBuddy 的功能入口清单（教学设计 / 家校共育 / 专业成长三大 tab）逐项对照后，
"教学内容生产"类空白集中暴露：教学动画、课件（PPT）、教案、学生评语、作业讲评稿。
这些能力形状高度相似——**按模板产内容 → 产出可预览的工件 → 老师在右栏看 → 按反馈迭代**。

当时摆在桌面上的三个实现选项：

- **A. 每种内容一个工具**：`generate_teaching_animation`、`generate_slides`、
  `generate_lesson_plan`……照这个路径，工具注册表会从今天的 46 个继续线性膨胀。
  Single Agent 架构下（ADR-0019）工具选择完全靠 docstring，工具越多选择越发散，
  且每个新内容种类都要改 `agent/tools/__init__.py` 的 TOOLS / TOOL_META、CI 冒烟断言
  （`assert len(TOOLS) == 46`）与 persona 过滤面。
- **B. 一套轻量"教学技能"注册表**：每个技能声明 prompt 模板、产物工件类型、参数
  schema、适用的既有校验；agent 侧只有一个入口工具按技能名分发。
- **C. 不做工具，纯对话产出**（WorkBuddy 路线）：我们没有它的技能基础设施，
  且纯对话没有四维审核、数据读取（讲评稿要吃批改数据）的挂载点。

## Decision

1. **选 B**。技能注册表是唯一的"教学内容生产"扩展点；新增一种内容 = 注册一个技能，
   不改 agent、不动 TOOLS 数量、不重跑工具选择评估。
2. **技能声明的四要素**：prompt 模板（含方法论沉淀，如动画的教学动线规范）、
   产物 Artifact 类型、参数 schema、依赖的既有校验（复用四维审核等，不新造）。
3. **斜杠指令是技能的快捷键**（/动画 /讲评），不是独立机制；@ 引用把附件与工件
   作为上下文带进提示词，替换裸 `upload_id` 拼接。
4. **schema 预留 `author` 字段但本期不开放老师自定义技能**：自定义 prompt 进他人
   上下文是注入面，涉及审核与数据边界，价值密度当前低于把内置技能做深。

## Consequences

- 工具数量稳定：内容种类增长不体现在 TOOLS 里，CI 冒烟断言不再跟着内容需求变。
- 技能质量集中在注册表一处治理（模板、审核、产物类型校验），符合"深模块"——
  agent 只见一个入口，复杂性收在注册表内部。
- 代价：入口工具的分发层是新的必测接缝；技能模板的版本管理（prompt 迭代）需要
  与工件版本联动设计，批次 A 方案文档里定。
