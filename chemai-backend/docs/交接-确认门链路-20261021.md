## 4. 还剩两条要修

### ① 【严重】原生 interrupt 试点：批准后不重放、门不关、不写决定

**只在 `CHEMAI_GATE_INTERRUPT=1` 时出现**，默认关闭。

复现：带开关跑上面那条 8 步任务，点第 4 步的「批准」→ 计划第 4–8 步全变「已放弃」，
库里：

```
GATE  g-tool-assign_adaptive_practice-…  status = open     ← 永远开着
DEC   (空)                                                ← 没有任何决定
RUN   completed，步骤 4–8 cancelled
```

日志证据：

```
POST /api/agent/chat/langgraph/resume  200 OK
GATE_OPEN_CALLED kind=boolean tool=assign_adaptive_practice caller=_suspended_gate_events
```

`assign_adaptive_practice` 是 `agent/guard.py` 里 `_INTERRUPT_PILOT` **唯一的成员**
—— 之前几次「跑通」全是草稿门，从没走过这条路。

**下一步**：在 `agent/channel/langgraph_channel.py:2347` 前加一行日志

```python
logger.warning("resume_dbg next=%s ints=%s want=%s",
               bool(getattr(_resume_state,"next",None)), len(_pending_ints), _want)
```

带开关跑一遍，看是 `next` 为空还是 `_pending_ints` 为空：

- `next` 为空 → 图已经不在挂起态（可能被后续 stream 覆盖）
- `_pending_ints` 空 → 挂起点没有持久化到 checkpointer，或 thread/config 不一致
- 两者都非空但 `_by_id` 空 → gate_id 对不上（guard 里 `_pilot_gid` 的算法要跟
  `_suspended_gate_events` 登记门行时用的算法逐字一致）

**未修期间的处置**：开关保持关闭。不要因为单元测试绿就开 ——
`tests/test_gate_interrupt_pilot.py` 是直接调 `_make_guarded_tool`，
**没走真实 channel 的 resume**，所以它对这条 bug 是盲的。

### ② 【中】布尔门的批准不写账本

`langgraph_channel.py:2145` 的账本写死在 `if gate_did:` 分支里 —— 只有草稿门记账。
布尔门走 `_direct_replay_events`（879 行）：`claim_gate` → 重放 → `finish_gate`，
全程不写 `agent_gate_decisions`，所以「谁批的这次布置练习」查无此人。

实测：8 步任务点了 3 次批准，`agent_gate_decisions` 只有 2 行。

**改法**：在 986 行 `_gs.finish_gate(db, _gid, _success)` 旁边，`_success` 为真时补
`_gs.record_decision_log(db, _gid, "approved", conversation_id=cid,
actor_user_id=…, tool_name=pending["name"], kind="boolean")`。

**障碍**：`_direct_replay_events(guard_state, approved, cid, gate_id)` 的签名**没有
actor_id**，要从决策入口透传（有 3 个调用点）。改之前先 grep 全部调用点。
